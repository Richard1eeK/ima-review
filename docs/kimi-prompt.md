# Kimi 界面设计提示词

由用户自行复制下面提示词到 Kimi，并提供项目中的 `package.json`、`shared/types.ts`、`shared/defaults.ts`、`docs/api.md` 以及当前 `src/`。本步骤不需要提供 ima 凭证、SQLite、JSON 备份或私人笔记全文。示例数据请使用自己编写的通用英语教学内容。

```text
请为我的个人英语学习应用重新设计并实现前端。它以 ima 笔记为学习来源，供一名英语教师持续学习词汇、短语、搭配、句型和辨析，既要看得舒服，也要真正好用。

视觉方向是当代中国风：把中国文化的气质转化为可信、清楚、有辨识度的交互设计。请充分发挥你的设计判断，自行决定配色、字体、版式、材质、视觉节奏、图形语言和动效。不要套用现成模板，也不要把传统符号简单堆满页面。无需等待我选择色板、字号或布局；请给出一套完整、统一且适合长期学习的方案。

实现环境是 React 19 + TypeScript + Vite。后端已经存在，正式运行时前端与 API 同一 origin。请先阅读 docs/api.md、shared/types.ts 和 shared/defaults.ts，然后替换或完善 src/。可改界面组件和样式，不要改变服务器、共享类型、凭证、数据库、安装脚本或 API。不要在浏览器加入模型调用、AI 自动评分、ima 访问凭证、分析追踪或未经许可的外部资源。

请完成以下使用链路，所有操作必须连接真实 API：
1. 今日学习：显示新学、复习、应用的任务、进度、日期与学习待办。默认限制取自接口，不在 UI 写死。
2. 词条学习：清楚展示词条、释义、中文、来源、例句、口语/写作表达、提醒、辨析成员及待补充状态。
3. 学习与独立作答：新学阶段以阅读笔记、释义、例句和提醒为主，用户确认理解后进入复习；不要在新学阶段再要求解释或提交回答。复习阶段再隐藏参考并要求用英语主动回忆；应用题使用造句、辨析、语域改写和常见误用等任务。开放回答提交后显示接口保存的笔记参考，再提供四档自评。不要声称用户的开放回答已被自动判对或判错。
4. 词库：搜索、标签、薄弱项、归档和待核对筛选；资料更新 needsRelearn 提示要让用户明确选择 useLatest。归档不能删除历史。
5. 作答档案：分别显示原答、修订、外部评阅反馈、自评、来源和时间，保存修订与反馈。可复制评阅包；只有用户主动点击才调用剪贴板。不自动发送资料到外部模型。
6. 导出和恢复：Markdown、CSV、完整 JSON、打印保存 PDF、一致性 SQLite 备份；恢复先校验，展示结果并由用户确认覆盖。下载使用真正的下载链接。
7. 设置和同步：可编辑学习数量、时区、同步时间、学习待办时间、笔记本选择、减少动效设置；展示同步状态、上次成功、错误和增改归档计数，支持手动同步。

下面是必须保留的行为约定：
- 使用接口响应和共享类型作为事实来源，不用假数据替代实际功能。
- 首次加载、空题库、没有到期复习、缺少来源内容、加载失败、同步失败、保存中、保存失败、已保存和恢复失败都要有清楚的状态与下一步。
- 草稿使用稳定 UUID。第一次写入 expectedRevision=0，后续写入使用服务返回的 revision；409 冲突要保留本地输入，提示服务端当前版本，让用户决定如何处理，不能静默覆盖。
- 请求失败、切换页面、切换题目、刷新和提交重试不能丢失正在输入的答案。保存提示必须区分未保存、正在保存和已由服务器保存；离线暂存不能冒充服务器成功。
- 提交后的 originalAnswer 不能被修订覆盖；修改写入 revisedAnswer 和 feedback。自评重复点击不能产生重复记录。
- 新学与到期复习按词条计数，辨析组是一条；新学只记录完成确认，英语主动回忆属于复习；应用题的自评只记录结果，不重复推进同一天的 FSRS。今日计划由服务器按日期稳定随机并持久化，不由前端重新随机生成。
- 不将参考内容提前泄露到作答界面；开始答题时记录的题目版本和来源应稳定。服务器标记 pending 的资料不应当进入今日计划。
- 任何 mutation 都以 application/json 发送。正确处理 ApiError 的 error、code、current。
- 移动端、桌面端、键盘导航、触屏、窄屏长文本、屏幕阅读器和打印布局都要可用。输入框不能被固定栏或软键盘挡住。

动效应服务于状态理解和操作反馈。以 60 fps 和高刷新率设备上的流畅体验为目标，使用浏览器可合成的属性，避免持续主线程重计算、大量布局抖动和无法停止的背景动画；不能在未实测时声称已经达到帧率。遵循 prefers-reduced-motion 和应用 reducedMotion 设置，减少动效时保留全部功能。字体与装饰资源优先本地，不依赖网络请求才能完成学习。

请交付实际可运行的 src/ 实现、必要的本地静态素材，以及简洁说明：设计思路、改动文件、运行方式和已验证/待验证的项目。运行 npm run build，验证完整作答、参考、自评、保存失败后重试、版本冲突、导出和窄屏输入流程。不要更改 API 来适配视觉稿，不要把没有调用过的接口写成已经成功，不要宣称目标 Mac、手机外网、Kimi 之外的系统部署已完成。
```

收到代码后，把 `src/` 集成到当前项目并重新构建，再按[接口行为](api.md)和[部署验收](deployment.md#验收)检查。该提示词是界面交付约束，不表示 Kimi 已运行或最终视觉已经验收。
